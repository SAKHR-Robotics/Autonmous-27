Benchmark Testing Suite

RViz Testing & Benchmark Guide

A comprehensive engineering guide for procedural benchmark map generation, closed-loop kinematics simulation (TF & Odometry), and validating Smac Planner and MPPI Controller under edge-case navigation scenarios.

Testing Suite Architecture

1. Benchmark Map Generator

A standalone Python script that algorithmically generates standardized obstacle benchmarks with .pgm occupancy grids and .yaml metadata (0.05m/pixel resolution).

testing/PathPlanner/scripts/generate_benchmark_maps.py
2. Kinematic Mock Base

Simulates closed-loop differential/skid-steer kinematics, listens to Nav2 velocity commands (/cmd_vel_nav), and broadcasts transforms (map ➔ odom ➔ base_link) and /odom.

testing/PathPlanner/scripts/mock_base.py
3. Nav2 Stack & RViz2

Executes Smac Hybrid A* global search and MPPI Controller dynamic trajectory optimization with live costmap inflation layers visualized in RViz2.

erc_path_planner/launch/path_planning.launch.py

Standard Benchmark Scenarios

1. Rock Field
rock_field.yaml

Design: 10m × 10m bounded arena containing 5 staggered rocks separated by 1.5m – 2.0m navigable corridors.

Verification Focus: Tests MPPI Controller dynamic trajectory optimization, smooth obstacle weaving, and optimal path-following without hesitation.

How to Test: Click 2D Goal Pose at the opposite end of the field across the obstacles, and observe the rover smoothly slalom between the rocks.
2. Narrow Corridor
narrow_corridor.yaml

Design: A horizontal dividing wall spanning the arena, punctured by a narrow 1.5-meter central gateway.

Verification Focus: Tests Inflation Layer safety clearance calculations and robot footprint centering to ensure collision-free passage through tight gaps.

How to Test: Place the goal pose on the other side of the wall, and verify the planner maintains equal distance from both door edges.
3. Dead-End Pocket
dead_end.yaml

Design: An enclosed U-shaped pocket / cul-de-sac with a single egress opening.

Verification Focus: Tests Smac Hybrid A* non-holonomic Reeds-Shepp reverse motion when forward turning is geometrically constrained.

How to Test: Use 2D Pose Estimate to position the robot inside facing the closed wall, then dispatch a goal outside the pocket.

RViz2 Interactive Controls Reference

2D Pose Estimate Reposition / initialize the robot starting pose (/initialpose) Click anywhere on the map grid and drag to define the heading direction. The mock base snaps to this pose instantly.

Troubleshooting & Best Practices

1. Robot is not moving after setting a goal?

Verify that Terminal 2 (mock_base.py) is actively running. If it was launched after setting the goal, simply click 2D Goal Pose again to dispatch a fresh command.

2. "No map received" warning on Global Costmap in RViz?

Ensure the Durability Policy under Topic is set to Transient Local (not Volatile). Toggle the display checkbox off and on to force an immediate QoS refresh.

3. Node startup timeout or lagging processes?

Conflicting background ROS nodes may be lingering in memory. Clean all orphan processes with a single command:

pkill -9 -f ros2 ; pkill -9 -f rviz ; pkill -9 -f nav2 ; pkill -9 -f mock_base
