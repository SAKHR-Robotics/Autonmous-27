ERC 2026 Path Planning Guide

Comprehensive Navigation & Global Planning Architecture for the ERC Rover

Localization → Smac Hybrid A* → MPPI → Rover Control

1. Global Path Planning Overview

The Global Planner acts like the GPS navigation routing system. It looks at the overall static global map and calculates the shortest mathematical route from the rover's current position to the destination.

How it works conceptually

  • It receives a coordinate destination (Goal Pose).
  • It reads the /map provided by SLAM.
  • It runs algorithms like A* (A-Star) or Dijkstra to draw a continuous line through cells that have a cost of 0 (free space), totally avoiding cells marked as 100 (lethal obstacles).
  • This is purely a mathematical path; it does not know how to steer the wheels or obey physics.

2. Global Planner: Why Smac Hybrid A*?

  • Considers rover kinematic constraints.
  • Produces smooth and feasible paths.
  • Supports turning radius limitations.
  • Works efficiently with costmaps.
  • Officially supported in ROS 2 Nav2.

State Representation & Cost Function

A* State       : (x, y)
Hybrid A* State : (x, y, θ)

f(n) = g(n) + h(n)

where g(n) = traveled cost, h(n) = estimated distance to goal.

Why is it suitable for ERC?

  • Handles rough terrain and generates realistic trajectories.
  • Reduces slipping and rollover risks.

3. Local Planner & Controller: Why MPPI?

In modern ROS 2 Nav2 architecture, the Local Planner and Controller are merged into one. MPPI (Model Predictive Path Integral) continuously generates thousands of short trajectories to follow the global path safely, and simultaneously calculates the motor velocities needed.

Optimization Function

J = Goal Error + Obstacle Cost + Path Deviation + Terrain Cost

Advantages

  • Real-time obstacle avoidance.
  • Smooth, cinematic motion generation.
  • Handles localization errors smoothly.
  • Excellent performance in unknown and rough terrains.

5. System Inputs, Outputs & Topics

To implement this system, these are the exact ROS 2 topics and coordinate frames required:

Critical Inputs

Topic / Transform Type Source Role in Path Planning
/goal_pose geometry_msgs/PoseStamped Mission State Machine The exact X, Y destination coordinates where the rover needs to drive.
/map nav_msgs/OccupancyGrid SLAM (RTAB-Map) The static global map used by Smac to find long-term obstacle-free routes.
/perception/obstacles_only vision_msgs/Detection3DArray Perception (Persistent Memory) Persistent 3D bounding boxes of rocks converted via Costmap Bridge into PointCloud2 for real-time MPPI avoidance.
/odometry/filtered nav_msgs/Odometry SLAM (EKF) High-speed (100 Hz) local velocity and pose feedback. Required by MPPI to calculate steering physics.
TF Tree tf2_msgs/TFMessage SLAM (EKF & RTAB) Transforms: map → odom → base_link. Crucial for Nav2 to know where the rover is on the map.

System Outputs

Topic Type Receiver Description
/plan nav_msgs/Path MPPI Controller The continuous array of coordinates forming the global route (drawn by Smac).
/cmd_vel geometry_msgs/Twist Rover Hardware The final steering and throttle velocities (linear X, angular Z) generated by MPPI to drive the motors.

6. Implementation & Configuration Brief

Implementing this stack utilizes the official ROS 2 Nav2 framework. You do not write custom C++ path planners; you strictly configure and tune the Nav2 plugins via parameters.

Step 1: Install Nav2

sudo apt install ros-humble-navigation2 ros-humble-nav2-bringup

Step 2: Configure the Nav2 Parameters (nav2_params.yaml)

You must map the Planner and Controller plugins inside your parameter file:

Smac Hybrid A* Configuration

planner_server: ros__parameters: expected_planner_frequency: 1.0 planner_plugins: ["GridBased"] GridBased: plugin: "nav2_smac_planner/SmacPlannerHybrid" motion_model_for_search: "REEDS_SHEPP" minimum_turning_radius: 0.8 allow_unknown: true

MPPI Controller Configuration

controller_server: ros__parameters: controller_frequency: 20.0 controller_plugins: ["FollowPath"] FollowPath: plugin: "nav2_mppi_controller::MPPIController" time_steps: 56 model_dt: 0.05 batch_size: 2000 vx_std: 0.2 vy_std: 0.2 wz_std: 0.4 vx_max: 0.5 wz_max: 1.3

Step 3: Launching

Create a ROS 2 launch file that boots the standard Nav2 bringup, pointing to your custom YAML file:

ros2 launch nav2_bringup navigation_launch.py params_file:=/path/to/nav2_params.yaml

8. Dynamic Obstacle Avoidance & Replanning Architecture

During the competition, when dynamic obstacles appear on the terrain, Nav2 coordinates local swerving and global replanning through the Behavior Tree:

flowchart TD BT["Behavior Tree Navigator
(Central Orchestrator)"] GP["Global Planner (Smac Hybrid A*)
Computes macro route /plan on Global Costmap"] LP["Local Controller (MPPI)
Evaluates 2,000 rollouts @ 20Hz on Local Costmap"] BT -->|"ComputePathToPose"| GP GP -->|"/plan"| BT BT -->|"FollowPath (/plan)"| LP LP -->|"20Hz Cycle"| EVAL{"Can MPPI swerve safely?"} EVAL -->|"YES"| DRIVE["Output /cmd_vel
(Swerve around rock & rejoin plan)"] EVAL -->|"NO (Trapped / Blocked)"| FAIL["Return FAILURE
(NO_VALID_TRAJECTORY)"] FAIL -->|"Trigger Immediate Replanning"| BT BT -->|"Compute Detour Path"| GP GP -->|"If Path Blocked Everywhere"| REC["Recovery Behaviors
1. Clear Costmap (Remove sensor noise)
2. BackUp 0.8m from Hazard
3. Spin 360° to Scan
4. Retry Plan"]

Coordination Principles

  • MPPI never talks to Global Planner directly; the Behavior Tree handles state transitions and replanning triggers.
  • Small Obstacles: MPPI's ConstraintCritic avoids the rock locally at 20 Hz without interrupting global navigation.
  • Major Blockages: When all 2,000 MPPI rollouts fail, BT immediately invokes Smac Planner to compute a fresh detour on the updated global costmap.

Conclusion

By defining Smac Hybrid A* as the Global Planner and merging Local Planning/Control into the MPPI plugin, we achieve a streamlined, high-performance architecture. This setup provides:

  • Feasible, smooth trajectories.
  • Robust obstacle avoidance using Costmaps.
  • Direct compatibility with ROS 2 Humble and Jetson Orin Nano.
  • A highly suitable solution for the ERC 2026 Traverse Task.
