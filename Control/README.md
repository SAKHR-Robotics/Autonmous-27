# Rover Control Subsystem & Hardware Interface Specification

This directory defines the kinematic specifications, hardware communication interfaces, and actuator driver contracts for the 4-wheel skid-steer autonomous rover.

---

## 📌 Kinematics & Hardware Architecture

The rover employs a **4-wheel skid-steer (differential drive)** kinematic layout driven by 4 DC drill motors coupled with incremental quadrature encoders:

- **Track Width ($B$)**: $0.65\text{ m}$ (lateral distance between left and right wheel contact patches).
- **Wheel Radius ($R$)**: $0.15\text{ m}$.
- **Drive System**: 4 drill motors (2 left, 2 right) wired in paired skid-steer configuration.
- **Microcontroller Interface**: STM32 / CAN-bus / UART motor controller firmware.

### Skid-Steer Inverse Kinematics
Given target linear velocity $v_x$ ($m/s$) and target angular yaw rate $\omega_z$ ($rad/s$) from `/cmd_vel`:

$$v_L = v_x - \frac{\omega_z \cdot B}{2}$$
$$v_R = v_x + \frac{\omega_z \cdot B}{2}$$

Target motor rotational velocities in RPM:
$$\text{RPM}_L = \frac{v_L}{2\pi R} \times 60$$
$$\text{RPM}_R = \frac{v_R}{2\pi R} \times 60$$

## 🧪 Standalone Verification Guide (World + Rover + Teleop)

To test the kinematic model, motor response, and encoder feedback in simulation:

### Step 1: Launch Mars Yard World & Rover
```bash
source install/setup.bash
# Run simulation with odom TF enabled for standalone driving verification
ros2 launch my_robot_description gazebo.launch.py publish_map_tf:=true bridge_sim_tf:=true
```

### Step 2: Launch Teleoperation Controller
```bash
source install/setup.bash
# Launch interactive graphical teleop
ros2 run my_robot_description teleop_gui.py
```
*(Or use standard keyboard teleop: `ros2 run teleop_twist_keyboard teleop_twist_keyboard`).*

### Step 3: Verify Kinematic Output & Velocity Commands
In a separate terminal, observe the velocity twist commands generated by the teleop interface:
```bash
ros2 topic echo /cmd_vel
```

Expected output when pressing forward:
```yaml
linear:
  x: 0.5
  y: 0.0
  z: 0.0
angular:
  x: 0.0
  y: 0.0
  z: 0.0
```

### Step 4: Verify Wheel Odometry Feedback
Verify that wheel rotations generate `/wheel/odom_raw` (or `/model/my_robot/odometry` in Gazebo):
```bash
ros2 topic hz /wheel/odom_raw
ros2 topic echo /wheel/odom_raw
```

## ⚙️ Topic Contract

| Topic | Type | Source | Consumer | Description |
| :--- | :--- | :--- | :--- | :--- |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | Nav2 MPPI / Teleop GUI | Motor Bridge / Gazebo | Target linear ($v_x$) and angular ($\omega_z$) speeds |
| `/wheel/odom_raw` | `nav_msgs/msg/Odometry` | Wheel Encoders | SLAM Slip Checker & EKF | Raw uncorrected wheel speed & orientation |
| `/model/my_robot/cmd_vel` | `geometry_msgs/msg/Twist` | ROS-GZ Bridge | Gazebo Diff Drive Plugin | Simulated actuator input |
