2. Full Architecture & Requirements Overview

A. Coordinate Frame Tree (TF Tree)

The system enforces a clean, single-parent transform hierarchy:

map  →  (RTAB-Map offset)  →  odom  →  (EKF 100Hz pose)  →  base_link
  • odom → base_link (Local Link): Published at 100 Hz by EKF. Continuous, smooth, zero coordinate jumps, used by local MPPI controller.
  • map → odom (Global Link): Published at 1–5 Hz by RTAB-Map. Absorbs global drift corrections and loop closures without jerking local wheel controllers.

B. Topic Data Pipeline Contract

/wheel/ticks / /wheel/odom_raw nav_msgs/msg/Odometry Wheel Encoder Driver Heuristic Slip Checker / EKF
/imu/data sensor_msgs/msg/Imu BNO055 IMU Driver Heuristic Slip Checker / EKF
/camera/color/image_raw sensor_msgs/msg/Image RealSense Driver RTAB-Map / ArUco Detector
/camera/depth/image_rect_raw sensor_msgs/msg/Image RealSense Driver Depth Post-Processing Filter

/perception/obstacles_only sensor_msgs/msg/PointCloud2 Perception Terrain Node Nav2 Costmap 2D Server

3.5. Milestone Validation Checkpoints

Use these explicit checkpoints to verify each milestone before merging code. Each checkpoint specifies the command to run, what to expect, and how to verify correctness.

Checkpoint 1: Static Transforms & Infrastructure (After 1A & 2B.1)

  • Trigger: Task 1A (Package setup) & Task 2B.1 (`static_transforms.launch.py`) completed.
  • Command to Run:
    ros2 launch rover_slam static_transforms.launch.py
    ros2 run tf2_ros tf2_echo base_link camera_link
  • Expected Output: TFs base_link → camera_link and base_link → imu_link are published continuously at 10 Hz with zero lookup errors.

Checkpoint 2: Sensor Pre-Processing & Depth Filters (After 2A.1 & 1B)

  • Trigger: Task 2A.1 (`encoder_ticks_to_odom.py`) & Task 1B (`vision_helper.launch.py`) completed.
  • Command to Run:
    ros2 launch rover_slam vision_helper.launch.py
    ros2 topic hz /camera/depth/filtered  |  ros2 topic echo /wheel/odom_raw
  • Expected Output: `/wheel/odom_raw` outputs linear/angular velocity Twist at 50+ Hz. Depth image feed `/camera/depth/filtered` publishes clean frames with decimation and 4.0m range clipping applied.

Checkpoint 3: Local EKF & Slip Checker (After 2A.2, 3A & 2B.2)

  • Trigger: Task 2A.2/2A.3 (EKF setup), Task 3A (slip checker), & mock ArUco publisher verified.
  • Command to Run:
    ros2 launch rover_slam ekf.launch.py
    ros2 topic pub /perception/aruco_pose geometry_msgs/msg/PoseStamped "{header: {frame_id: 'camera_link'}, pose: {position: {x: 1.0}, orientation: {w: 1.0}}}" -1
    ros2 topic echo /odometry/filtered
  • Expected Output: (1) `/odometry/filtered` & odom → base_link TF publish smoothly at 100 Hz. (2) When simulated wheel slip occurs, `heuristic_slip_checker.py` increases covariance on `/wheel/odom_raw`. (3) Verify receipt of the mock 6-DOF pose on `/perception/aruco_pose` without needing the real Perception module.

Checkpoint 4: RTAB-Map SLAM & Costmap 2D Server (After 4A, 5A & 4B) — Completed & Verified

  • Trigger: Task 4A/5A (RTAB-Map setup) & Task 4B/5B (Costmap server + test stub) completed.
  • Command to Run:
    ros2 launch rover_slam rtabmap.launch.py  |  ros2 launch rover_slam costmap.launch.py
    ros2 run tf2_ros tf2_echo map odom  |  ros2 topic echo /global_costmap/costmap
  • Expected Output: RTAB-Map publishes map → odom TF frame and static `/map` grid. Costmap 2D server fuses `/map` + test obstacle point cloud and outputs inflated `/global_costmap/costmap`.

Checkpoint 5: Master System Bringup & Rosbag Benchmark (After 6 & 7) — Completed & Verified

  • Trigger: Task 6 (`slam_bringup.launch.py`) & Task 7 (system integration) completed.
  • Command to Run:
    ros2 launch rover_slam slam_bringup.launch.py
    ros2 run rviz2 -d src/rover_slam/config/slam_visualization.rviz
  • Expected Output: Complete TF tree (map → odom → base_link → camera_link) is clean with 0 warnings. Robot trajectory renders smoothly at 100 Hz. Rocks appear correctly inflated on `/global_costmap/costmap`.

4. Person 1 Task Track (State Estimation & SLAM Backend)

Independence Guarantee: Person 1 works on state estimation and mapping. Person 1 can test the EKF using raw wheel/IMU topics and test RTAB-Map using raw camera depth feeds or mock ArUco topics without waiting for Person 2's vision code.

Task 1A.1: Package Infrastructure Setup
Initialize `rover_slam` ROS 2 package in `Autonmous_Ws/src/`. Configure `setup.py` / `CMakeLists.txt` and `package.xml` with dependencies (`robot_localization`, `rtabmap_ros`, `sensor_msgs`, `nav_msgs`, `geometry_msgs`).
Task 1A.2: Directory Structure Creation
Create workspace subdirectories: `config/`, `launch/`, `rover_slam/`, and `test/`.
Task 2A.1: Wheel Encoder Odometry Pre-Processor Node
Implement `rover_slam/encoder_ticks_to_odom.py`. Read raw wheel ticks `/wheel/ticks`, calculate differential drive linear/angular velocities, and publish `nav_msgs/msg/Odometry` to `/wheel/odom_raw`.
Task 2A.2: Local EKF YAML Configuration
Create `config/ekf.yaml` for `robot_localization`. Set `world_frame: odom`, `frequency: 100`, `two_d_mode: true`. Fuse wheel linear velocity (X, Y) from `/wheel/odom_raw` and IMU orientation/yaw rate from `/imu/data`.
Task 2A.3: Local EKF Launch File
Create `launch/ekf.launch.py` to start `ekf_node` with parameters loaded from `config/ekf.yaml`. Verify that `/odometry/filtered` and `odom -> base_link` TF are published at 100 Hz.
Task 3A.1: Heuristic Slip Checker Pre-Filter Node
Develop `rover_slam/heuristic_slip_checker.py`. Subscribe to `/wheel/odom_raw` and `/imu/data`. Calculate linear speed difference ($|V_{wheels} - V_{imu}| > 0.15\text{ m/s}$) and angular yaw rate difference ($\omega_{wheel} \neq \omega_{imu}$).
Task 3A.2: Dynamic Covariance Publishing Logic
Add logic to `heuristic_slip_checker.py` to scale up wheel velocity covariance values when slip is flagged, dynamically reducing EKF trust in the wheels during sand slippage.
Task 3A.3: Slip Checker Unit Test Suite
Create `test/test_slip_checker.py` to test synthetic wheel spin inputs and verify covariance adjustment outputs.
Task 4A.1: RTAB-Map YAML Parameters Configuration
Create `config/rtabmap.yaml`. Configure loop closure detection thresholds, visual feature extraction (FAST/GFTT), memory management, and GTSAM graph optimizer settings.
Task 4A.2: RTAB-Map Launch Setup
Create `launch/rtabmap.launch.py`. Configure RTAB-Map to subscribe to `/odometry/filtered` (from EKF) and depth images. Set `publish_tf: true` for `map -> odom`.
Task 5A: ArUco Landmark Channel Configuration
Configure RTAB-Map launch file to map `/perception/aruco_pose` (contract topic with Person 2) to RTAB-Map's landmark input topic (`/rtabmap/landmark`) as global graph constraints.
Task 7A: RViz 2 State Estimation Dashboard
Create `config/slam_visualization.rviz` displaying the TF tree, `/odometry/filtered` trajectory path, RealSense point clouds, and static `/map` grid.

5. Person 2 Task Track (Sensors Pre-Processing, Vision & Costmap)

Independence Guarantee: Person 2 works on camera filtering, static TFs, ArUco detection, and Costmap 2D. Person 2 can test camera filters directly on the RealSense stream, test ArUco detection on sample images, and test the Costmap server using `costmap_test_stub.py` without waiting for Person 1.

Task 1B.1: RealSense D435 Filter Configuration
Create `config/realsense_filters.yaml`. Configure `realsense2_camera` driver filter options: Decimation, Spatial, Temporal, Hole-filling filters, and clip max depth range to 4.0 meters.
Task 1B.2: Vision Helper Launch File
Create `launch/vision_helper.launch.py` launching `realsense2_camera` node with post-processing filters enabled, publishing cleaned topic `/camera/depth/filtered`.
Task 2B.1: Static Transforms Launch File
Create `launch/static_transforms.launch.py` broadcasting static sensor frames: `base_link -> camera_link`, `base_link -> imu_link`, and `camera_link -> camera_depth_optical_frame`.
Task 3B.1: ArUco Pose Subscription & Detector Node
Implement `aruco_detector_node.py` (PnP pose solver) and `mock_aruco_publisher.py` for decoupled `/perception/aruco_pose` testing with RTAB-Map SLAM.
Task 4B.1: Nav2 Costmap 2D Configuration
Create `config/costmap_params.yaml` for `nav2_costmap_2d`. Define Static Layer (`/map`), Obstacle Layer (`/perception/obstacles_only`), and Inflation Layer.
Task 4B.2: Costmap Server Launch Setup
Create `launch/costmap.launch.py` to start `nav2_costmap_2d` lifecycle nodes.
Task 5B: Perception Obstacle Test Stub & Costmap Verification
Develop `rover_slam/costmap_test_stub.py` to publish dummy rock obstacle point clouds. Verify that `nav2_costmap_2d` correctly inflates rock safety bubbles and outputs `/global_costmap/costmap`.

6. Joint Integration & System Verification Tasks

Integration Phase: Executed jointly once Person 1 and Person 2 complete their independent tracks.

Task 6.1: Master System Bringup Launch File

Task 6.2: Nav2 Lifecycle Transition Management
Configure Nav2 lifecycle manager to automatically transition `costmap` and `rtabmap` nodes from `unconfigured` to `active` state upon startup.

Verify: (1) Local EKF `odom -> base_link` runs smoothly at 100 Hz, (2) Slip checker increases wheel covariance on wheel spin, (3) `map -> odom` updates on loop closures/ArUco tags, and (4) `/global_costmap/costmap` inflates obstacles for the planner.
